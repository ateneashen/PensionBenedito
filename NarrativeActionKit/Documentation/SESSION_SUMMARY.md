## 🏗️ Architecture Highlights

### Design Principles Applied

1. **Project-Agnostic Core**
   - All NAK classes are generic and reusable
   - No game-specific code in the framework
   - Games inherit and extend

2. **Component-Based Architecture**
   - Each system is an independent component
   - Mix and match as needed
   - Easy to add/remove functionality

3. **Data-Driven Design**
   - Behavior configured through DataAssets
   - Designers can modify without code changes
   - Easy iteration

4. **GAS Integration**
   - Gameplay Ability System for attributes
   - Effects for damage/healing/buffs
   - Tags for state management

5. **UE4.27 Compliance**
   - No TObjectPtr (UE5 only)
   - Raw pointers with UPROPERTY
   - Classic input system
   - Proper delegate binding

### Naming Conventions

| Prefix | Meaning | Example |
|--------|---------|---------|
| `NAK` | NarrativeActionKit | `NAKCharacterBase` |

## 🎓 Lessons Learned

### What Worked Well
1. **Component-based architecture** — Clean separation
2. **Project-agnostic design** — Truly reusable
3. **Local LLM for research** — High quality, low risk
4. **Skills for model local** — Prevents loops, improves quality

### Challenges Overcome
1. **UTF-8 encoding** — Avoid special characters in prompts
2. **Model loops** — Use skills with token limits
3. **UE4.27 compliance** — No TObjectPtr, classic input

### Best Practices Established
1. **One class per file** — Easy to find and maintain
2. **Public/Private split** — Clean API
3. **Prefix naming** — NAK for framework, PB for game
4. **Component-based** — Prefer over deep inheritance
